# Ansible Role Manager

Manages Ansible roles under `src/kube_eng/ansible/project/roles/`.

## Arguments

The user invoked this with: `$ARGUMENTS`

Parse arguments as:
- Keyword `create` anywhere: scaffold a new role (role name required, follows the keyword)
- Keyword `validate` anywhere: run validation only, do not create
- Role name with neither keyword: default to `create`
- Neither keyword, no role name: validate all roles

## Behaviour

### Create a new role

When a role name is given with `create`:

1. **Scaffold** with ansible-galaxy:
   ```bash
   ansible-galaxy role init --init-path src/kube_eng/ansible/project/roles <role-name>
   ```

2. **Add the SPDX license header** to every generated `.yml` file:
   ```yaml
   #SPDX-License-Identifier: MIT-0
   ```
   Files to patch: `tasks/main.yml`, `handlers/main.yml`, `defaults/main.yml`, `vars/main.yml`, `tests/test.yml`.

3. **Overwrite `meta/main.yml`** with the project boilerplate:
   ```yaml
   #SPDX-License-Identifier: MIT-0
   galaxy_info:
     author: MrMatAP
     description: <Short description — ask the user if not provided>
     company: The MrMat Organisation
     license: MIT
     min_ansible_version: 2.1
     galaxy_tags: ['kube-eng']
   dependencies: []
   ```

4. **Create `meta/argument_specs.yml`** — this file is NOT generated by ansible-galaxy and is required:
   ```yaml
   # Argument requirements. See https://docs.ansible.com/ansible/latest/dev_guide/developing_program_flow_modules.html#argument-spec
   ---
   argument_specs:
     main:
       short_description: <Short description matching meta/main.yml>
       options: {}
   ```
   Ask the user what arguments the role will accept so you can populate `options` properly. Each option entry follows this structure:
   ```yaml
   options:
     <param_name>:
       description: <What this parameter controls>
       type: str        # str | int | bool | list | dict | path | float | raw
       required: true   # or false
       default: <value> # omit when required: true
       choices: []      # omit when unconstrained
   ```

5. Update the `README.md` file with the role name. It is important that the Role Variables section has all options 
   as described in `meta/argument_specs.yml`. Their types and descriptions must match the options in 
   `meta/argument_specs.yml`. If there are discrepancies then consider `meta/argument_specs.yml` to be more 
   trustworthy. If in doubt, look at the roles Ansible tasks and any variables used in `templates`. Generate the 
   Example Playbook section using the fully-qualified `mrmat.kube_eng.<role-name>` namespace — always include
   the namespace prefix. Omit obvious dependencies for simplicity:
   ```yaml
   - name: Example invocation of <Role Name>
     hosts: localhost
     tasks:
     - name: <Short role description>
       ansible.builtin.import_role:
         name: mrmat.kube_eng.<role-name>
       vars:
         <variable>: <example value>
   ```

6. Confirm the role is ready and show the user the directory tree.

### Validate existing roles

When `validate` is given (or no role name):

For each role under `src/kube_eng/ansible/project/roles/`:

- Check that `meta/argument_specs.yml` exists.
- Check that it contains an `argument_specs.main` key.
- Check that every parameter listed in `argument_specs.main.options` has at minimum `description` and `type`.
- Check that `meta/main.yml` exists and has `galaxy_info.author = MrMatAP`.
- Check that `README.md` exists, contains the role name and all options listed in `meta/argument_specs.yml`.
- Check that `README.md` has an example playbook with matching options from `meta/argument_specs.yml`.
- Check that the example playbook uses the fully-qualified `mrmat.kube_eng.<role-name>` namespace (not a bare role name).
- Report PASS / FAIL per role in a table. Offer to fix any failures.

## Key paths

- Roles directory: `src/kube_eng/ansible/project/roles/`
- argument_specs reference: https://docs.ansible.com/ansible/latest/dev_guide/developing_program_flow_modules.html#argument-spec

## Examples

```
/mrmat-ansible-role create dns_extra_zone    # create a new role
/mrmat-ansible-role validate                 # validate all existing roles
/mrmat-ansible-role helm_deploy validate     # validate one specific role
```
