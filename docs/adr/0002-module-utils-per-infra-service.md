# module_utils per Infra service, thin Ansible modules on top

Playbook tasks that called out to raw Python (or one-off inline logic in `library/*.py` modules) were tedious to maintain and impossible to unit test, since `AnsibleModule` couples argument parsing, execution, and result reporting into one script. We're splitting each Infra service's logic into a `module_utils/<service>_utils.py` — plain Python, importable and unit-testable, built on the shared `InfraResult`/`InfraException` base classes in `module_utils/base.py` — with thin `library/*.py` Ansible modules on top that only translate `module.params` into calls against the util layer. `idp` (`module_utils/idp_utils.py`, `library/idp_client.py`, `library/idp_validate.py`, `tests/infra/test_idp.py`) is the reference implementation other Infra services (`dns`, `pg`, `s3`, `registry`, `kafka`) are being converted to follow.
